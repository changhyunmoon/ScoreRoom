# 화면 품질과 구현 순서

## 디자인과 공통 UI

기존 네이비/화이트 기반 사내 포털 디자인, 카드형 메인과 게시판형 업무 화면을 유지한다. styles.css의 색상·간격·모서리·레이어 순서 변수를 공통 토큰으로 정리하고 기능 CSS는 해당 기능이 소유한다. 새로운 UI 프레임워크나 전체 디자인 교체를 전제로 하지 않는다.

공통 UI는 Button, Field, Dialog, Toast, Empty, Loading, ErrorState, Pagination, ConfirmAction부터 정리한다. 로딩 버튼은 중복 클릭을 막고 작업 중임을 텍스트와 함께 표시한다. 오류가 있는 필드는 aria-invalid/설명 연결과 인라인 문구를 제공한다. 저장 성공과 실패를 색상만으로 구분하지 않는다.

팝업은 role/label 외에 초기 포커스, Tab 포커스 가두기, Escape 닫기, 닫은 후 호출 버튼으로 포커스 복귀를 구현한다. 미저장 폼은 바깥 클릭으로 조용히 사라지지 않도록 이탈 확인을 둔다. 토스트는 aria-live를 제공하되 폼 오류의 유일한 표시 수단으로 사용하지 않는다.

발표 순서 드래그에는 위/아래 이동 버튼을 함께 제공해 키보드/터치에서도 조작할 수 있게 한다. 상세 표는 적절한 table 헤더를 사용하고 좁은 화면에서 표 영역만 가로 스크롤되게 한다. 검증 화면 폭은 초기 제안으로 360px, 768px, 1440px이며 실제 기기에서 폼/팝업/평가 입력을 확인한다.

## 1. 현재 동작을 유지하며 경계 분리

router/layout을 App.tsx에서 분리하고 공통 UI, 표시 함수, 기능 타입을 옮긴다. Admin의 결과 컴포넌트를 results로 분리한다. 단계마다 기존 화면과 npm run build를 확인한다. 폴더 이동과 API 계약 변경을 한 번에 하지 않는다.

완료 기준: 기존 경로, 관리자 탭, 팝업, 평가 입력, 결과 이미지 생성이 유지되고 기능 간 순환 import가 없다.

## 2. HTTP와 인증 기반

shared HTTP client, ApiError, CSRF, `/me`, 세션 가드를 구현한다. Vite 프록시와 로컬 Spring을 연결한다. TanStack Query는 이 단계에서 도입하며 추가 버전은 package-lock에 고정한다. 운영 mock 진입점을 제거한다.

완료 기준: 새로고침 로그인 유지, 세션 만료 안내, 403 화면 구분, 서버 로그아웃, 사용자 전환 시 캐시 제거, CSRF 검증 실패 처리. 가입/복구는 서버의 본인 확인 정책이 준비된 기능만 노출한다.

## 3. 화면별 서버 상태 전환

룸 목록 → 룸/발표 상세 → 내 평가 → 초대 → 운영/설정 → 결과 → 조직 관리 순으로 전환한다. `/state` 어댑터로 연결한 화면은 전환 완료 후 기존 store 의존을 제거한다. URL 검색 조건을 반영하고 조회 시 로딩/빈 결과/오류를 구분한다.

완료 기준: 서로 다른 두 브라우저에서 같은 룸과 점수를 공유한다. dirty 점수/피드백은 폴링 뒤에도 유지된다. 룸 마감/권한 회수 뒤 저장은 서버 응답에 맞게 차단된다. 결과 집계와 PNG는 같은 서버 결과를 사용한다.

## 4. 복합 작업과 품질

설정 변경 영향 미리보기, 멤버 제거 확인, 파일 일부 실패 재시도, 충돌 안내, 모바일/키보드 접근을 마무리한다. 평가 중 서버를 사용할 수 없으면 입력을 유지하고 복구 후 최신 상태를 조회한다. 초안을 브라우저 저장소에 자동 영속화하는 기능은 개인정보 보존 정책을 정한 뒤 별도로 검토한다.

## 검증 계획

Vitest/React Testing Library로 입력 상태와 사용자 행동을, HTTP mock으로 오류/응답 계약을, Playwright로 실제 브라우저 흐름을 검증하는 안을 제안한다. 이 도구는 현재 설치되지 않았다. 실제 백엔드와 통합하는 E2E는 가상 계정/독립 DB에서 수행한다.

| 시나리오 | 검증 기준 |
|---|---|
| 점수 0, 음수 범위, 공백, 소수 | 허용 범위/정수 검사; 빈 값이 0으로 제출되지 않음 |
| 저장 더블클릭/Enter 반복 | 동일 대상의 요청 중복 억제, 성공 후 상태 일치 |
| 입력 중 자동 갱신 | draft 보존, 서버 변경과 구분 |
| 저장 후 응답 유실 | 미확정 상태 안내 후 조회; 무조건 재제출하지 않음 |
| 설정 영향 확인 후 데이터 변경 | 409 재조회·재확인 |
| 일반 참여자/열람자/운영자 | 접근과 결과 상세 노출 구분 |
| 다른 사용자로 재로그인 | 이전 점수/피드백/연락처 캐시와 폼 노출 없음 |
| 파일 일부 업로드 실패 | 성공/실패 항목 구분, 실패만 재시도 |
| 결과 PNG | 긴 이름/한글/동점/데이터 없음/폰트 로딩 후 출력 |
| 키보드와 좁은 화면 | 모든 기능 접근, 포커스 복귀, 버튼 겹침 없음 |

프런트의 요청량/재렌더/대용량 표 성능은 실제 데이터로 측정한다. 화면 페이지네이션이 모든 행을 내려받은 뒤 자르는 것인지 서버 페이지네이션인지 구분하고, 전체 합계는 서버 전체 데이터 기준으로 표시한다.

## 후속 결정

- React/Router/Vite 업그레이드와 Query 도입의 정확한 버전.
- 동점 순위 방식과 상위 N명 이미지에서 동점 포함 범위.
- 검색/페이지 URL 유지 범위와 초안 보존 정책.
- 초기 가입/본인 확인·복구 정책에 맞는 화면 문구.
- 백엔드가 돌려줄 capability와 결과 상세 DTO의 OpenAPI 계약.

이 문서의 폴더/도구/조회 주기는 권장안이며 실제 구현은 후속 작업이다.
